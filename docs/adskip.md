# 跳广告 Beta · 原理说明

> 适用版本：Pro `v5.8.8-pro` 起。功能默认关闭，设置路径：**设置 → 播放行为 → 跳广告 Beta**。

## 1. 它解决什么

部分采集源的视频流里会插入固定模板的广告片段：中央是「闲 / 庄 / 和」三色按钮，左右各三张游戏卡，整体深红加金色，音频几乎整段相同，只有网址字幕在变。

这类广告不是普通商业贴片，而是同一套模板批量生成。版式、配色、音频骨架高度一致，因此不需要通用广告识别模型，用三路低层证据即可稳定判断。

功能只处理**视频流内的独立广告片段**，不处理角标、滚动字幕、正片内口播，也不触碰付费或 DRM 内容。

## 2. 三路判据

| 证据 | 权重 | 说明 |
| --- | --- | --- |
| 中央三色按钮 | 0.40 | 按钮区蓝 / 黄 / 绿三色像素占比，与基准做高斯比对 |
| 音频指纹 | 0.40 | 40 维对数频带能量，z-score 后与内置模板算余弦 |
| 红金配色 | 0.20 | 全画面红色与金色占比，与基准做高斯比对 |

融合得分：

```
score = 0.40 × 按钮 + 0.40 × 音频 + 0.20 × 配色
```

判定条件：

```
(按钮 ≥ 0.90 且 音频 ≥ 0.85)        → 直接判定
或 score ≥ 0.85 连续 2 次（1 秒）    → 判定
```

双高门控优先，是因为按钮与音频同时精确匹配时，正片几乎不可能命中。

### 2.1 按钮区

按 1920×1080 标定的相对坐标：

```
x = 0.22917   y = 0.61111
w = 0.57292   h = 0.21296
```

抽帧统一缩放到 480×270，因此实际 ROI 为 `x 110–385, y 165–222`。

HSV 判定（H 为 0–360，S/V 为 0–1）：

| 颜色 | H 范围 | S | V |
| --- | --- | --- | --- |
| 蓝 | 190–260 | > 0.353 | > 0.275 |
| 黄 | 40–68 | > 0.353 | > 0.275 |
| 绿 | 80–170 | > 0.353 | > 0.275 |
| 红 | ≤ 24 或 ≥ 336 | > 0.275 | > 0.157 |
| 金 | 26–70 | > 0.275 | > 0.353 |

基准占比：蓝 0.210、黄 0.156、绿 0.191、红 0.563、金 0.244。

注意：Python/OpenCV 的 H 是 0–180，浏览器里自写的 HSV 是 0–360。移植阈值时必须乘 2，否则蓝色会落到绿色区间，整条判据失效。

## 3. 音频指纹

### 3.1 特征

- 采样率 48kHz，FFT 2048 点，帧移 512。
- 频率范围 60–7600Hz，按对数分成 40 个频带。
- 每个频带取平均幅度，`log1p(mean × 100)`。
- 每秒聚合一次，得到 40 维向量。
- 向量做 z-score（减均值、除标准差），消除响度与设备差异。
- 与内置模板算余弦相似度，映射到 0–1。

### 3.2 为什么用指纹而不是分类

同一模板的广告，音频整段几乎相同，只有网址播报段可能不同。指纹比对比训练分类器更直接：

- 不需要训练数据；
- 换域名不影响；
- 计算量极小，40 维点积。

实测同一条 23.6 秒样本，23 个 1 秒窗口与模板的余弦相似度均值约 0.976。

### 3.3 音频不可用时

Safari 原生 HLS 直连远端 m3u8，媒体跨域，`createMediaElementSource` 可能输出静音。运行时检测到连续 3 秒频谱低于 -90dB，即判定音频不可用，自动降级为纯视觉：

```
score = 0.60 × 按钮 + 0.40 × 配色
门控：按钮 ≥ 0.95 且 配色 ≥ 0.85
```

## 4. Worker 预判

逐像素 HSV 转换在主线程做会占用 2–4ms，低端设备可能掉帧。因此拆成两层：

```
主线程                           Worker
────────                        ────────
video → canvas 480×270
getImageData
postMessage(transfer)  ───────▶  逐像素 HSV
                                 三色占比 / 红金占比
onmessage              ◀───────  {btn, col}
融合音频得分
状态机 / seek / 提示
```

- 抽帧每 500ms 一次，ImageData 通过 transfer 零拷贝传给 Worker。
- Worker 只做视觉，音频特征与状态机留在主线程（依赖 AnalyserNode 与 video 元素）。
- 上一条结果未返回时跳过本次抽帧，避免消息堆积。
- Worker 创建失败（CSP 禁止 blob worker）时自动降级为主线程同步计算。

## 5. 跳过与撤销

### 5.1 状态机

```
IDLE → WARMUP（3s）→ MONITOR
                        │ 连续 2 次命中 / 双高门控
                        ▼
                       AD → seek +15s → COOLDOWN（3s）→ MONITOR
```

- 播放开始或切集后 3 秒内不判定，等缓冲稳定。
- 每次跳过 +15 秒，最多连续 4 次（覆盖 60 秒广告），之后暂停 10 分钟。
- 广告结束后不自动回退，避免正片重复播放。

### 5.2 提示与取消

跳过时在播放器底部显示：

```
已跳过广告 00:12.4 → 00:27.4    [取消]
```

- 提示保留 8 秒。
- 点「取消」立即 seek 回起点，并在本集内禁用自动跳过。
- 切集后重置禁用状态。

## 6. 阈值来源

阈值不是拍脑袋定的，来自实测样本：

| 指标 | 实测值 |
| --- | --- |
| 按钮区蓝 / 黄 / 绿占比 | 0.211 / 0.152 / 0.192 |
| 全画面红 / 金占比 | 0.530 / 0.226 |
| 按钮与配色高斯得分 | 0.97–0.99 |
| 音频余弦 | 0.93–0.99 |
| 构造广告帧 | btn 1.000 / col 0.988 |
| 全黑帧 | btn 0.0004 / col 0.035 |

正负样本分离度足够，因此进入阈值取 0.85，按钮门控取 0.90。

## 7. 局限

1. **只覆盖当前模板。** 对方换游戏卡、换配色、换语言后，按钮占比与音频指纹都会变，需要更新基准与音频模板。
2. **无法预读未来。** 实时检测只能看已播内容，广告开头通常残留 1–2 秒。
3. **赌场题材影视可能误判。** 正片里出现赌桌、筹码、红金配色时，按钮占比可能接近；靠音频指纹与双高门控压制，但仍需保留「取消」。
4. **Safari 可能只有视觉。** 音频不可用时精度下降，阈值已相应收紧。
5. **超过 60 秒的广告需要多轮。** 单次 +15 秒，最多 4 次。

## 8. 隐私

- 所有抽帧、音频特征、判定都在本地内存完成。
- 不上传画面、音频或识别结果。
- 不落盘、不写日志、不接入统计。
- 只有本地 `localStorage` 保存一个开关状态。

## 9. 模板更新

需要更新时，改三处：

1. `AD_BETA.btnRef`：蓝 / 黄 / 绿基准占比。
2. `AD_BETA.colorRef`：红 / 金基准占比。
3. `AD_BETA.audioRef`：40 维音频模板。

采样与特征管线必须与第 3 节一致：48kHz、FFT 2048、60–7600Hz 分 40 带、log1p、z-score。否则余弦会整体偏移。

更新后用 `window.adSkip.state` 观察实时得分，确认正样本稳定在 0.85 以上、负样本在 0.5 以下，再发布。

## 10. 调试

浏览器控制台可用：

```js
adSkip.start()   // 启动
adSkip.stop()    // 停止
adSkip.state     // 查看 audio、hits、worker 状态
```

`adSkip.state.audio` 是当前音频余弦，`adSkip.state.audioOk` 表示音频通道是否可用，`adSkip.state.workerFail` 表示 Worker 是否降级。
